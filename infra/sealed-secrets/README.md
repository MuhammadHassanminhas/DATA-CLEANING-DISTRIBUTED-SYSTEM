# Sealed Secrets

Encrypted cluster Secrets, safe to commit. This is what makes the
platform reproducible from a fresh clone (CLAUDE.md §13) without ever
putting a plaintext credential in Git (§12).

Before this existed, cluster Secrets came only from the gitignored
`.env` via `bootstrap-secrets.ps1`, so a clone on a machine without that
`.env` could not bring an environment up.

## How it works

The sealed-secrets controller (installed by Terraform in Step 1.5.1)
holds a private key. `kubeseal` encrypts a Secret with the matching
public key, producing a `SealedSecret` that only that controller can
decrypt. The encrypted form is useless to anyone else, so it is safe in
a public repository.

Seals here are **strict-scoped** (the default): each one is bound to its
name *and* namespace. A SealedSecret sealed for `staging` cannot be
unsealed into `production`, which is why staging and production have
separate files even where the underlying value is the same.

## Files

| File | Namespace | Contents |
|---|---|---|
| `staging-app-secrets.yaml` | staging | `ENROLLMENT_SECRET`, `CREDENTIAL_PEPPER` |
| `staging-postgres-secret.yaml` | staging | `POSTGRES_PASSWORD` |
| `staging-tls-certs.yaml` | staging | coordinator + dashboard certs/keys, dev CA |
| `staging-dashboard-basic-auth.yaml` | staging | ingress basic-auth htpasswd |
| `production-app-secrets.yaml` | production | `ENROLLMENT_SECRET`, `CREDENTIAL_PEPPER` |
| `production-postgres-secret.yaml` | production | `POSTGRES_PASSWORD` |
| `production-tls-certs.yaml` | production | coordinator + dashboard certs/keys, dev CA |
| `observability-grafana-admin.yaml` | observability | Grafana admin user/password |
| `observability-alertmanager-webhook.yaml` | observability | Alertmanager chat webhook URL |

`pub-cert.pem` is the controller's **public** key. Committing it is
intentional and safe — it lets anyone seal a new secret without cluster
access (`kubeseal --cert pub-cert.pem`).

Not sealed, deliberately:

- `platform-tls` — issued and renewed by cert-manager from Let's
  Encrypt. Sealing it would fight the issuer.
- `sh.helm.release.*` — Helm's own release state.
- `kube-prometheus-stack-admission` — generated by the chart's webhook.

## Applying

The namespaces must exist first (Terraform creates them).

```powershell
kubectl apply -f infra/sealed-secrets/
```

The controller decrypts each SealedSecret and writes the real Secret
alongside it, usually within a second. Verify:

```powershell
kubectl get sealedsecret,secret -n staging
```

**Note on ownership.** The generated Secret is owned by its SealedSecret,
so deleting the SealedSecret garbage-collects the Secret. On a cluster
where these Secrets already exist from `bootstrap-secrets.ps1`, applying
takes ownership of them — the values are identical, so nothing restarts,
but it is a real change of ownership. `bootstrap-secrets.ps1` remains
valid for local Docker Compose work and for bootstrapping a brand-new
controller before anything is sealed.

## Re-sealing after a rotation

Rotate the value in `.env`, re-run `bootstrap-secrets.ps1` for the
namespace, then re-seal from the live Secret:

```powershell
kubectl get secret app-secrets -n staging -o json > raw.json
python strip.py raw.json clean.json   # drop metadata (see below)
kubeseal --format yaml --controller-namespace sealed-secrets `
  --controller-name sealed-secrets -f clean.json > staging-app-secrets.yaml
```

**Strip the metadata before sealing.** `kubectl get secret -o json`
includes a `kubectl.kubernetes.io/last-applied-configuration` annotation
that embeds the entire Secret in cleartext, and `kubeseal` copies
annotations into the SealedSecret's template. Sealing the raw output
would publish the plaintext inside a file headed for Git. Keep only
`metadata.name`, `metadata.namespace`, `type`, and `data`.

Always confirm before committing:

```powershell
kubeseal --validate --controller-namespace sealed-secrets `
  --controller-name sealed-secrets -f <file>
```

## Disaster recovery

If the controller's private key is lost, every file here becomes
undecryptable and the secrets must be regenerated from `.env` with
`bootstrap-secrets.ps1` and re-sealed against the new key. Back up the
controller key if that matters to you:

```powershell
kubectl get secret -n sealed-secrets -l sealedsecrets.bitnami.com/sealed-secrets-key -o yaml
```

Treat that output as a root credential — it decrypts everything in this
directory. Do not commit it.
